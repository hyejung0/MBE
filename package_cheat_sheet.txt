===============================================================================
                       R PACKAGE DEVELOPMENT CHEAT SHEET
===============================================================================

Run these commands from the package project unless noted otherwise.


-------------------------------------------------------------------------------
1. DAILY DEVELOPMENT LOOP AND KEYBOARD SHORTCUTS
-------------------------------------------------------------------------------

# Load the package for interactive development without installing it
devtools::load_all()          # Mac: Cmd + Shift + L | Windows: Ctrl + Shift + L

# Generate help files (.Rd) and NAMESPACE from roxygen2 comments
devtools::document()          # Mac: Cmd + Shift + D | Windows: Ctrl + Shift + D

# Run the testthat test suite
devtools::test()

# Install the package locally
devtools::install()           # Mac: Cmd + Shift + B | Windows: Ctrl + Shift + B

# Run the complete package quality check
devtools::check()             # Mac: Cmd + Shift + E | Windows: Ctrl + Shift + E

# Target before pushing: 0 errors, 0 warnings, and 0 notes


-------------------------------------------------------------------------------
2. CREATING AND DOCUMENTING FUNCTIONS
-------------------------------------------------------------------------------

# 1. Create a new R script in R/
usethis::use_r("function_name")

# 2. Write the function, place the cursor inside it, and insert a roxygen
#    documentation skeleton:
#      Mac:     Cmd + Option + Shift + R
#      Windows: Ctrl + Alt + Shift + R
#      Menu:    Code -> Insert Roxygen Skeleton

# 3. Complete the relevant roxygen2 fields:
#' @description Explain what the function does.
#' @param arg1 Explain the first argument.
#' @param arg2 Explain the second argument.
#' @return Describe the returned object and its structure.
#' @export
#' @examples
#' result <- function_name(arg1, arg2)

# 4. Regenerate documentation after changing roxygen2 comments
devtools::document()

# Use @export only for functions that should be part of the public API.

===============================================================================
                    STANDARD WORKFLOW FOR UPDATING THE PACKAGE
===============================================================================

1. Pull the latest changes and confirm the working tree is understood.
2. Edit functions, tests, documentation, data, or vignettes as needed.
3. Use devtools::load_all() for quick interactive checks.
4. Run devtools::document() after changing roxygen2 comments or exports.
5. Run devtools::test() and fix any failures.
6. Run devtools::build_readme() if README.Rmd changed.
7. Run devtools::check(); aim for 0 errors, 0 warnings, and 0 notes.
8. Optionally run pkgdown::build_site() and pkgdown::preview_site() locally.
9. Review git status and the diff, then commit and push the source changes.
10. Confirm that the R CMD check and pkgdown GitHub Actions both succeed.
11. Confirm the deployed website at https://hyejung0.github.io/MBE/.
